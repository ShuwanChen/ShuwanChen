# ShuwanChen · AI 产品作品集

**AI 产品 / AI Native 产品经理实习方向**

我关注如何把业务问题转化为可使用、可维护的产品。这份作品集展示 6 个招聘与人力资源场景的项目，覆盖 AI 工具发布、数据分析、流程自动化及配套工作台。

**6 个项目均由我单人负责需求、设计、部署、迭代、维护与推广，开发使用 Codex 辅助完成。** 我将个人的产品判断与 AI 辅助实现分开说明，重点展示用户路径、规则边界、交付闭环和持续维护。

## 先看这三个案例

| 项目 | 要解决的问题 | 产品思考与交付重点 |
| --- | --- | --- |
| **[AI 工具发布与治理平台](projects/ai-platform.md)** | AI 生成页面之后，如何交付给业务人员持续使用？ | 从生成/上传到资源检查、发布、分享、更新和下架；权限、配额与外链审批 |
| **[招聘数据运营平台](projects/recruit-analytics.md)** | 多份招聘表格如何变成能解释、能核对、能协作的结果？ | 指标口径、来源追踪、异常反馈、任务进度与报告导出 |
| **[员工关系测算与文书平台](projects/employee-calculator.md)** | 如何把复杂规则、方案确认和文书生成衔接起来？ | 确定性计算与 AI 咨询的分工、分阶段录入、批量处理及数据隔离 |

## 从单个工具到持续使用

| 配套项目 | 用户价值 | 展示的产品能力 |
| --- | --- | --- |
| [日常招聘数据工作台](projects/daily-workbench.md) | 导入/采集更新数据，在看板查看指标并回查来源 | 数据更新体验、采集状态恢复、未知值与零值的区分 |
| [数字化工作台门户](projects/workbench-portal.md) | 为多个工具提供统一的导航和访问入口 | 信息架构、应用配置、访问与管理权限及后台维护 |
| [浏览器扩展更新服务](projects/extension-updates.md) | 扩展发布后可检查版本并获取对应安装包 | 版本生命周期、升级路径、下载边界及运维可见性 |

这些项目展示不同业务环节，数据接入和系统集成各有配置要求；作品集不将它们描述为已自动打通的一体化系统。

## 我希望通过项目展示什么

- **需求与流程设计**：从具体业务任务出发，设计输入、结果解释、确认、交付与反馈路径。
- **AI 产品判断**：把 AI 用于内容生成与辅助开发；对金额、指标、权限等关键结果保留规则、校验与人工确认。
- **完整交付**：兼顾用户界面、部署配置、身份与数据边界，以及上线后的版本更新、迭代和维护。
- **可验证的表达**：案例区分已实现能力、测试证据、已知限制和后续评估指标；不以功能数量代替业务效果。

项目实现主要使用 Python / Flask、SQLite、原生 JavaScript，涉及 Excel/Word 处理、浏览器扩展、OAuth / PKCE、SSE 及文件存储集成。
