# HR 工具统一入口：让工具可发现、可维护

[返回作品集首页](../README.md)

## 产品位置与问题

这是 HR 数字化工具的配套入口，展示产品发现、角色权限和日常运营设计。员工需要找到合适的业务工具，管理员需要维护链接、分类和可用状态。入口若分散在消息或文档中，使用者容易遇到旧链接，维护者也难以追溯修改。

本项目将这些需求收敛为一个可搜索的门户。AI 能力由独立服务提供，门户负责引导使用者进入对应产品。

## 用户路径与设计选择

员工通过“查看分类 → 搜索工具 → 读取说明与状态 → 打开业务系统”完成查找。管理员通过“维护入口 → 调整排序或显隐 → 查看操作记录”保持导航可用。当前实现包含分类卡片、搜索、响应式页面、后台管理、支持邮箱和审计。

| 设计问题 | 当前选择与取舍 |
| --- | --- |
| 如何接入多个工具 | 统一维护链接，各业务工具独立运行；接入简单，但工具自身可用性需另行管理 |
| 谁可以使用和管理 | SSO 识别身份，IAM 分别校验访问与管理权限；服务异常时拒绝访问 |
| 如何追溯变更 | 导航变更和审计写入同一 SQLite 事务，记录修改前后内容 |
| 如何控制实现复杂度 | Flask、原生前端与 SQLite 支持轻量部署；多实例前需调整共享存储 |

## 个人职责与 AI 协作

我独立负责需求分析、产品设计、部署、迭代、维护与推广，使用 Codex 辅助代码实现。项目由一人推进全流程；本案例以当前实现说明产品选择，业务收益仍需通过使用数据验证。

## 验证证据与边界

2026-10-12 迁移验证中，现有自动化测试 **28 项通过、0 项失败**，覆盖导航管理、输入校验、审计、SSO、角色权限和 CSRF。测试使用临时数据库与模拟身份服务，未验证真实企业网络、生产部署或关联业务工具。

本地可关闭 SSO/IAM 体验后台，此时访问者具备管理员能力，仅适合本机开发。GitHub 展示的是脱敏源码快照，未包含运行数据库或员工记录。

## 下一步如何衡量

建议后续采集：从门户到工具的点击转化率、搜索无结果率、失效链接数量、入口维护耗时。以上是待验证指标，尚无本案例可披露的实测数值。
