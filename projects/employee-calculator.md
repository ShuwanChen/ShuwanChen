# 员工关系测算工具：规则、确认与文书的完整流程

个人独立项目 · AI 产品 / AI Native 产品经理方向 · Codex 辅助开发

## 业务问题

员工关系处理涉及工资、任职日期、假期和文书字段。只展示一个金额难以解释计算过程，测算与协议分开操作又需要重复录入。本项目面向 HR 工作场景，将规则测算、方案确认与 Word 文书生成连接起来，同时支持多人批量处理和本人数据隔离。

## 用户路径

用户填写基础信息或上传 Excel，查看 N / N+1 / 2N 及分段过程，选择方案后补充文书字段、确认金额并下载协议。待确认记录可恢复，历史记录支持再次计算；批量任务先核对逐人结果，再生成协议 ZIP。管理员管理城市参数、模板与设置。

**录入 → 看懂结果 → 确认方案与字段 → 生成文书 → 回看或再次计算**

## 关键产品取舍

- **确定性规则负责金额，AI 提供可选咨询。** 金额由独立计算引擎生成，展示公式与分段过程；AI 不替代金额确认和文书审核。项目重点是业务口径的可核验实现，不把模型回答直接当作计算结果。
- **分阶段收集信息。** 先完成测算，再在确认协议时补充身份、公司与合同字段，配合待确认状态支持用户中断后继续处理。
- **配置能力与历史稳定性兼顾。** Word 占位符驱动表单，公式字段由服务端计算；保留模板版本快照，避免模板更新改变已有记录使用的文书结构。
- **管理权限与业务内容访问分开。** 记录、协议和 ZIP 按用户归属校验；管理员可维护规则和模板，但不会因此获得其他用户的员工测算详情。

## 已实现范围与证据

版本 3.3.1，使用 Python / Flask、SQLite、原生 JavaScript，并通过 Excel 与 Word 库处理批量输入和文书输出。金额使用 Decimal，覆盖年限分段、工资月份和假期折算等规则，最终方案由用户确认。

2026-10-12 的 Windows / Python 3.12 验证记录为 **66 项测试通过、0 项失败**，覆盖计算边界、模板公式与版本、批量文书、CSRF 和用户数据隔离；模板结构与程序填充检查通过。演示使用合成数据，真实身份/AI 服务与生产部署未在本次迁移验证中联调，Word 未做逐页视觉排版确认。实际业务口径与文书需另行复核，本案例不提供法条结论。

## 后续如何验证产品价值

以下是待观察的产品指标，**尚未形成实测收益结论**：

- 任务完成率：开始测算后完成确认与文书生成的比例，识别用户在哪个环节退出。
- 返工原因：再次计算和重新生成的原因分布，区分输入更正、业务口径和模板问题。
- 批量处理质量：导入错误率、需要手工修正的行数，以及从上传到下载 ZIP 的耗时。
