# AI 应用交付平台：从生成页面到持续使用

个人独立项目 · AI 产品 / AI Native 产品经理方向 · Codex 辅助开发

## 业务问题

业务用户拿到静态页面或 AI 生成的网站后，仍需处理素材缺失、访问范围、更新和下架。生成成功只是一个节点，完整产品需要让产物进入可访问、可维护的使用流程。本项目将网站发布与可选 AI 建站放在同一工作台，并提供权限、配额、审批和审计能力。

## 用户路径

用户上传 HTML / ZIP，或通过外部 AI 服务生成网站；平台检查文件、资源引用与容量，发布后提供分享链接。用户可管理访问名单、有效期和站点数据，更新时复用原链接，结束使用时下架。管理员独立处理额度与外链审批。

**上传或生成 → 检查产物 → 发布与分享 → 更新 → 下架**

## 关键产品取舍

- **基础能力可独立使用。** 手工上传和 AI 建站共用发布流程；外部 AI 尚未配置时，静态网站管理仍可使用，避免把所有任务都绑定到模型调用。
- **明确 AI 能力边界。** 对话生成由外部 AgentArk 服务提供，本项目实现用户授权、流式交互、产物检查和部署，不宣称自研模型。生成结束后仍需确认存在可部署的网站包。
- **审批绑定具体内容。** 外链审批与网站内容摘要关联，入口或素材变化后撤销旧审批，让审核范围跟随实际发布内容。
- **允许交互，同时限制执行范围。** 上传页面可执行前端脚本，使用浏览器沙箱和资源策略限制访问；站点只提供受控 JSON 存储，不运行上传的后端程序。

## 我的职责

独立负责需求分析、产品设计、开发实施、部署、迭代、维护和推广，使用 Codex 辅助开发。产品工作覆盖用户路径、异常状态、能力边界和发布后的管理。当前版本包含资源引用修复、分片上传、会话重连/取消、原链接更新等体验细节；这里展示已实现能力，不以功能数量替代用户价值验证。

## 已实现范围与证据

版本 0.7.0，使用 Python / Flask、SQLite、原生 JavaScript；支持本地或 S3 兼容文件存储，以及 OAuth + PKCE、流式会话、网站包校验、访问控制和审批流程。

2026-10-12 的 Windows / Python 3.12 验证记录为 **135 项测试通过、2 项失败**；失败涉及临时目录判断与并发文件替换的 Windows 行为。Ruff、主要 JavaScript 语法及 8 项前端控制器检查通过。外部身份和 AI 测试使用模拟接口，真实服务联调与 Linux 完整运行尚未在本次迁移验证中确认。

## 后续如何验证产品价值

以下是待设计埋点并验证的指标，**尚无实测成效数字**：

- 首次发布成功率：从开始上传或建站，到获得可访问链接的完成比例，分入口统计失败原因。
- 产物可用率：AI 完成会话后，通过资源检查并可部署的网站包占比。
- 更新体验：完成一次内容更新的耗时、失败率，以及旧链接继续可用的比例。
